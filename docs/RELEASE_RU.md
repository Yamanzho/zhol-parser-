# Жол 0.2.0: локальная установка и миграция

Это локальный кандидат. Публичный выпуск на GitHub не создаётся. Рабочая база этой проверкой не изменялась.

## Что входит

- Поиск компании идёт по ключам, а не по всем компаниям города.
- Сомнительный кандидат не присоединяется молча.
- CSV и JSON пишутся порциями. Прежний предел в 5 000 строк снят.
- Excel по-прежнему вмещает не больше 1 048 575 строк данных. Для большего объёма выберите CSV или JSON.
- Команда `python -m zhol.cli rebuild-match-keys` заново строит ключи и не меняет компании.
- Команда `python -m zhol.cli identity-report` только печатает неподтверждённые пары снимков.

Версия пакета, приложения FastAPI и панели: `0.2.0`. Пути API остаются `/api/v1`.

## Установка

На компьютере, где Жол уже стоит в `.venv`:

```bash
python -m pip install -e ".[dev]"
```

Демонстрация без базы собирается заново так:

```bash
scripts/build-macos-demo.sh
```

Готовое приложение не открывает PostgreSQL и не ходит на карты.

## Миграция

Остановите API и сборщики. Сделайте копию базы. Затем, указав адрес своей базы в `DATABASE_URL`:

```bash
alembic upgrade b6d2f4a81c30
```

Миграция добавляет таблицу `company_match_keys` и индексы. Существующие компании, снимки и идентификаторы площадок она не переписывает. Ключи заполняются из текущего имени компании и из телефонов последнего снимка каждой площадки.

Если компании когда-либо записывались прямым SQL в обход приложения, после наката выполните:

```bash
python -m zhol.cli rebuild-match-keys
```

Повторять команду безопасно. Запустите API только после успешного наката.

Проверка без изменения строк:

```bash
python -m zhol.cli identity-report
```

## Откат

Снова остановите API.

```bash
alembic downgrade e5a9b3c20f41
```

Откат удаляет ключи и индексы этой миграции. Строки компаний, снимков и идентификаторов площадок остаются. После отката поиск компании снова читает город целиком, как до `0.2.0`.

Если накат оборвался, PostgreSQL откатывает всю миграцию целиком: таблица ключей не остаётся наполовину созданной. Повторите `alembic upgrade b6d2f4a81c30`.

## Прямой SQL

Обычные записи приложения сами обновляют ключи. Прямой `INSERT` и `UPDATE` в `companies` или `card_snapshots`, а также пакетная вставка мимо ORM, ключи не обновляют. Пока не выполнена пересборка, повторный импорт той же компании может создать вторую запись. Это поддерживаемый обходной путь только вместе с `rebuild-match-keys`.
