# Развёртывание Жол на macOS

Единственная точка входа: `scripts/zhol-deploy-macos.sh`. Она заменяет ручные `docker compose build` и `up`.
Прошлое развёртывание без `docker-compose.offline.yml` дало около 2,5 минуты простоя API: без override у API нет
`ZHOL_CONFIG_DIR`, и он падает при старте. Скрипт передаёт Compose оба файла всегда и игнорирует `COMPOSE_FILE`.

## Команды

```bash
scripts/zhol-deploy-macos.sh check                      # проверка и план, ничего не меняет
scripts/zhol-deploy-macos.sh deploy                     # спросит слово РАЗВЕРНУТЬ
scripts/zhol-deploy-macos.sh deploy --expect-commit <SHA>
scripts/zhol-deploy-macos.sh rollback                   # вернуть образы прошлого развёртывания
```

`--yes` отключает вопрос. `--expect-commit` останавливает развёртывание, если `HEAD` не тот коммит, который разрешили.
Скрипт не переключает коммиты, не делает `git fetch`, `pull` и `push`.

## Порядок работы `deploy`

Пока не пройдены все проверки, работающие службы не трогаются.

1. Docker Desktop отвечает, оба файла Compose на месте, есть `tests/golden/review-engine/config/models.yaml`.
2. В файлах сборки нет незакоммиченных изменений. Иначе образ нельзя повторить по коммиту.
3. `.env`: заданы `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `ZHOL_LOCAL_GATE` (не короче 32 символов),
   `ZHOL_ADMIN_TOKEN`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY`. Разрешения браузера, если заданы,
   должны быть одним из двух допустимых текстов. Значения не печатаются, только «задано».
4. Итоговая конфигурация Compose (`config --format json`) собрана из обоих файлов: у API есть `ZHOL_CONFIG_DIR`,
   `ZHOL_LOCAL_ACCESS`, локальный вход и том `/offline-config`, у воркера тома fixtures и admin, база на томе `pgdata`,
   порты только на `127.0.0.1`. Сама конфигурация не печатается: в ней пароль базы.
5. База запущена и `healthy`, `pg_isready` отвечает, ревизия Alembic прочитана.
6. Нет задач в работе, нет задач сбора в очереди (`collector`, `browser`), нет пакетов сбора в `running`.
   Скрипт задачи не останавливает и не создаёт: дождитесь окончания или поставьте пакет на паузу в панели.
7. Свободно не меньше 5 ГБ на диске Mac и в диске Docker (`ZHOL_DEPLOY_MIN_FREE_GB`).
8. Сборщик macOS: запомнить, работал ли он. Если работал, нужен допустимый `ZHOL_2GIS_BROWSER_GRANT`.
9. План: какие группы образов собирать (`app`: api, worker, browser-worker, scheduler; `web`: панель).
   Сборка нужна, если изменились файлы сборки с прошлого развёртывания этим скриптом или образ собран не им.
10. Текущие образы работающих служб получают теги `zhol-rollback/<проект>-<служба>:<время>`,
    запись в `data/deploy/rollback/<время>.json`.
11. Сборка. Службы в это время работают.
12. Проверка новыми образами, без замены служб: `zhol.cli schema-check` (ревизия базы равна ревизии кода),
    `zhol.deploy_probe` в api (запуск API с настоящими настройками), worker и browser-worker (тот же код и ревизия),
    версия панели в образе, сборщик macOS из `.venv` (тот же код), все пути, которые вызывает панель, есть в новом API.
13. Пересоздаются только службы с новым образом, изменённой конфигурацией или запущенные без override.
    База не перезапускается никогда. Сборщик macOS останавливается только если меняются api или воркеры.
14. После замены: `/health` API, службы работают и не перезапускаются, главная страница панели, `/health` через
    прокси панели, версия в `/openapi.json`, пути панели в работающем API.
15. Успех: запись `data/deploy/state.json` и `history.jsonl`, сборщик macOS запускается, если работал до этого.
16. Сбой проверки: автоматический откат пересозданных служб на сохранённые образы и повторная проверка.
    Сборщик macOS после отката не запускается: код каталога новее отката, включите его после разбора.

Повторный `deploy` того же коммита ничего не собирает и не перезапускает.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | развёрнуто или уже соответствует коммиту |
| 1 | проверка не пройдена, службы не перезапускались |
| 2 | неверные аргументы |
| 3 | новая версия не прошла проверку, выполнен откат, API отвечает |
| 4 | откат не помог или прерывание, нужен человек |

## Чего скрипт не делает

- Не запускает миграции. Схема старее кода: остановка и совет «Обновить базу Zhol.command».
- Не трогает контейнер базы, том `pgdata`, `data/backups`.
- Не удаляет образы (`rmi`, `prune`). Теги отката копятся, чистить их вручную.
- Не запускает профиль `collector` Docker и не создаёт задачи сбора.
- Не делает `git push`.

## Журналы

`~/Library/Logs/Zhol/deploy-<время>-<pid>.log`, права 600. В журнале команды, их коды и вывод сборки,
но не значения секретов. Каталог меняется переменной `ZHOL_DEPLOY_LOG_DIR`.

## Первое развёртывание этим скриптом

`data/deploy/state.json` ещё нет, поэтому скрипт соберёт обе группы образов. Слои возьмутся из кеша сборки.
Пересоздаются только службы, чей образ после сборки отличается от работающего.

## Ручной откат

```bash
scripts/zhol-deploy-macos.sh rollback
```

Берёт последнюю запись `data/deploy/rollback/*.json`, возвращает теги `<проект>-<служба>` на сохранённые образы,
проверяет схему старым образом api, пересоздаёт службы и проверяет `/health`. Если схема не подходит старому образу,
теги возвращаются как были, службы не трогаются.
