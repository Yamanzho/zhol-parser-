# E5: локальный заказ

Дата: 11.10.2026. Это подготовка заказа без Бека, без оплаты и без правки карточки.

## Команды

```bash
python -m zhol.cli create-test-order --spec order.json
python -m zhol.cli order-status --order-id <id>
python -m zhol.cli check-order-readiness --order-id <id>
```

Тот же приём есть у локального API: `POST /api/v1/local/orders`, `GET /api/v1/local/orders/{id}`, `GET /api/v1/local/orders/{id}/readiness`. Это не маршруты Бека из архитектуры, раздел 10.

## Что записывается

Заказ создаётся в этапе `created` через `transition()`. Следующий разрешённый переход по-прежнему `prepay_invoiced`. Этот этап его не делает и счёт не пишет. В `amount_kzt` лежит тариф на 1, 2 или 3 филиала: 30 000, 50 000 или 75 000 тенге. Это сумма заказа, не оплата.

Ключ повтора: `local-test:<key>` в `deals.syntony_deal_id`. Повтор с тем же ключом откатывается и не оставляет второй заказ. Новая компания берёт `id_2gis`, название и город из запроса. Адрес, телефоны и услуги пишутся только если их прислал клиент, со ссылкой на сообщение или файл. `approved: false` остаётся неподтверждённым фактом. Пароль текстом не принимается.

Готовность: `ready` или `not_ready`, плюс четыре списка: не хватает данных компании, материалов, разрешения владельца, не сняты разночтения. `ready` не ставится, пока по каждой выбранной площадке нет `verified`. Проверка не открывает браузер и не меняет этап заказа.
