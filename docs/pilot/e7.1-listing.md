# E7.1: план правок карточек

Дата: 11.10.2026. Это подготовка создания и обновления карточек в 2ГИС, Яндекс Бизнесе и Google Business Profile. Форма не отправляется.

## Команда

```bash
python -m zhol.cli dry-run-listing --order-id <id> --pages pages/ --evidence data/listing/<id>
```

`--pages` это каталог сохранённых страниц `2gis.html`, `yandex.html`, `google.html`. Живой кабинет эта команда не открывает.

## Что делает прогон

Заказ читается локально. Для каждой площадки код решает `create` или `update`, сравнивает утверждённые факты с уже сохранённым снимком или с сохранённой страницей и пишет поле за полем. Повтор с тем же итогом не добавляет вторую строку правки и вторую запись журнала.

Если нет утверждённых названия, адреса или телефонов, или ни на одной площадке нет `verified`, прогон останавливается до журнала. Отказ одной площадки не стирает журнал другой. Стена входа, проверка «не робот» или код из СМС ставят паузу и задачу человеку. Пароль код не вводит и шифр из `credentials` не читает.

Готовый контент E6 подключается, только если строка `content_items` в статусе `checked` и помечена `illustrative: true`. Если E6 ещё не готов, правки по фактам клиента всё равно планируются. Сгенерированные фото работ, зала и мастеров не публикуются.

Не каждое поле пишется на каждой площадке. Сайт в 2ГИС это `link`. Счётчик цен остаётся наблюдением, список услуг пишется отдельно там, где он есть в `editable_fields`. В Google в этом пакете не пишутся услуги, WhatsApp и Instagram. Описание остаётся только для чтения, пока для него нет отдельного факта клиента.
