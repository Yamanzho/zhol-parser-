# E7.3: подготовка правок в кабинете 2ГИС

Дата: 11.10.2026. Команда заполняет поля уже выбранной организации и останавливается перед «Сохранить». Форма не отправляется, публичная карточка не считается изменённой, новая карточка не создаётся.

## Команда

```bash
python -m zhol.cli prepare-2gis-listing --order-id <id> --page tests/fixtures/cabinet/2gis-editor.html --evidence data/listing/<id>
```

`--page` в тестах и в обычном прогоне это сохранённый HTML кабинета. Живой адрес `https://...` открывается только при `ZHOL_2GIS_CABINET=1`, в обычном видимом окне без сохранённого профиля. Пароль программа не вводит.

## Что делает прогон

Сверяет id организации и видимое название с заказом. Роль в кабинете должна быть владелец или представитель. Чужая организация, наблюдатель или неподтверждённый доступ останавливают прогон до записи.

Пишет только утверждённые факты, которые ещё не совпадают с полем: название, адрес, рубрика, телефон, сайт (`link`), часы, услуги и цены. Описание и отметка «цены» остаются только для чтения. WhatsApp и Instagram пишутся, только если контроль уже есть в кабинете и значение утверждено. Телефон и рубрика на существующей карточке ждут отдельное «да» клиента. Картинки в этом шаге не загружаются.

Повтор с тем же итогом не добавляет вторую строку журнала. Скриншоты до и подготовленного состояния и `review.json` лежат в каталоге доказательств. Задача человеку `2gis_listing_review` остаётся открытой: это разрешение на следующий этап, не на отправку из этой команды.

Стена входа, проверка «не робот», код из СМС или повторный вход ставят паузу. Код и пароль в доказательства не записываются.
