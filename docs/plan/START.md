# Старт: с чего начать Ерболу

## 1. Подготовка (один раз, 30 минут)

1. Распаковать пакет. Создать **приватный** репозиторий `zhol` на GitHub.
2. Разложить пакет:

| Из пакета | Куда в репозитории |
|---|---|
| `source/AGENTS.md` | `AGENTS.md` (корень) |
| `START.md`, `00-README.md`, `01-arkhitektura.md`, `02-priemka.md`, `03-proverka-i-konsilium.md`, `04-slovar-dannyh.md`, `stages/` | `docs/plan/` |
| `prompts/` | `prompts/` |
| `council/` | `council/` |
| `skills/*` | `.claude/skills/*` |
| `source/` (кроме `AGENTS.md`) | `source/` |

3. В корне создать `CLAUDE.md` с одной строкой: `@AGENTS.md`.
4. В `.gitignore` добавить `source/base-contacts.csv`: там контакты 550 компаний, в git их не храним, на сервер файл загружается отдельно
   (описать в `docs/runbook.md`). `source/etalon-50.csv` остаётся в репозитории: на нём тесты.
5. Поставить готовые скиллы из `00-README.md`.
6. Получить у Тимура **лично, не в чате:**
   - ключи Anthropic, OpenAI, Google (Gemini); Telegram-бот и id чата ответственного (до S0);
   - сервер (решение Р4) (до S0);
   - доступ к аккаунтам Duna с правами менеджера на карточке AOE в 2ГИС, Яндекс Бизнесе, Google Business Profile (до S5);
   - материалы AOE для тестового заказа: логотип, 10-20 реальных фото, прайс услуг, график, контакты (до S4);
   - контакт разработчиков Syntony и тестовый тенант (до S3).
7. Попросить Тимура ответить на решения Р1-Р8 (`00-README.md`). План от них не блокируется, но ответы лучше получить до S3.

Файлы в `source/`, которые только для справки: `audit_card.py` и `render.cjs` (пути внутри них ведут на машину Тимура, их не запускать;
нужна только логика `score()` и вёрстка), `pilot-out/` (образец вёрстки одностраничника, тексты не копировать),
`AOE_2GIS_September_2026.xlsx` (образец оформления отчёта, данные другие).

## 2. Первое сообщение в Claude Code

Открыть репозиторий в Claude Code и отправить:

```text
Ты работаешь над сервисом «Жол» для Duna.kz. Я Ербол, разработчик. Заказчик Тимур.

Прочитай по порядку:
1. AGENTS.md (ТЗ);
2. docs/plan/START.md, 00-README.md, 01-arkhitektura.md, 03-proverka-i-konsilium.md, 04-slovar-dannyh.md, 02-priemka.md;
3. список файлов в docs/plan/stages/, prompts/, council/checklists/, .claude/skills/, source/.

Потом ответь коротко:
- как ты понял продукт, в 5 строках;
- как устроена проверка задач и консилиум, в 5 строках;
- этапы и их порядок с учётом зависимостей;
- что непонятно или противоречит друг другу в документах (если ничего, так и скажи);
- что нужно от меня до начала S0.

Код пока не пиши. После моего ответа начнём S0 через скилл zhol-stage.
```

Дальше на каждом этапе: `/zhol-stage Sx`, затем вставить «Промт для ИИ-разработчика» из `docs/plan/stages/Sx.md`.
Один этап = одна новая сессия: ИИ заново читает документы и не тащит за собой старый контекст.

## 3. Если работаете в Codex (ChatGPT)

Codex читает `AGENTS.md` из корня сам. Поддержку скиллов в формате `SKILL.md` проверьте в своей версии Codex.
Не подхватываются: в начале каждого этапа вставляйте текст нужных `skills/*/SKILL.md` перед промтом этапа.

Ревью кода другим ИИ (`03` раздел 3.2): что написано в Claude Code, отдать на ревью в Codex, и наоборот.

## 4. Правила работы с ИИ

- Не принимать «готово» без вывода тестов и команд.
- ИИ предлагает отступить от архитектуры: пусть объяснит, решение в `docs/decisions.md`.
- Документы противоречат друг другу: старшинство из `00-README.md`; вопрос Тимуру с вариантами А и Б.
- Вопросы Тимуру собирать списком раз в день.
