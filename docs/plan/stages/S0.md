# S0. Каркас, движок проверки и консилиум

**Зависит от:** ничего. **Длина этапа:** самый большой, на нём стоит всё остальное.

## Цель

Рабочая основа сервиса: база со всеми таблицами, переходы статусов, очередь, обёртка над моделями, движок проверки
(один проверяющий и консилиум), прогон золотых наборов, подмена времени, уведомления, импорт эталона и перенос расчёта балла.
После S0 каждый следующий этап только добавляет агента и подключает его точку проверки.

## Входы

- `docs/plan/01-arkhitektura.md` (всё), `docs/plan/03-proverka-i-konsilium.md` (всё), `docs/plan/04-slovar-dannyh.md` (раздел 1)
- `source/audit_card.py` (функция `score()`; файл только для справки, пути внутри него не используются)
- `source/karty-metodika-2026-10.md` (раздел 6, версия 1.1), `source/etalon-50.csv`
- Промты `prompts/council-*.md`, `prompts/executor-fix-reply.md`; чек-лист `council/checklists/dev-stage.md`
- От Тимура: ключи Anthropic, OpenAI, Google (Gemini), Telegram-бот и id чата

## Шаги

1. Репозиторий по разделу 2 архитектуры, `docker-compose.yml` с `db`, `api`, `worker`, `browser-worker`, `scheduler`.
2. Миграция Alembic: все таблицы раздела 3 архитектуры и таблицы `council_runs`, `council_items`, `review_quality` из `03`, раздел 9.
3. `transition(obj, to)`: переходы раздела 4 архитектуры. Недопустимый переход: исключение. Тест на каждый недопустимый переход заказа.
4. Очередь `jobs`: постановка с `dedup_key`, взятие с `SKIP LOCKED`, очереди `main` и `browser`, повторы 1/5/30 минут, `dead` → `human_tasks` + Telegram.
5. `timeutil.now()` и флаг `--now` для всех команд CLI и `scheduler`.
6. Обёртка `llm.run()` по разделу 6: три провайдера, проверка схемы, повтор, переменные, `llm_calls` со стоимостью.
   Проверка при запуске (семейства по `review_policy.yaml`, `vision` у моделей для картинок, цены): не выполнено, сервис не стартует.
7. Движок `review.run(point, object_type, object_id)` строго по `03`, разделы 2, 4-7:
   уровень «один проверяющий», консилиум (круг 1, круг 2, секретарь, подсчёт голосов кодом, кворум, вердикт в заданном порядке),
   возврат автору через `executor-fix-reply`, повторные круги до 3, `human` с доводами, запись в `council_runs` и `council_items`,
   режимы `double_read` и `double_decision`, надбавка `kazakh_text`.
8. `python -m zhol.cli eval --prompt <имя>` и `--point <точка>`: прогон золотого набора, доля прошедших, список провалов.
9. `python -m zhol.cli council-dev --stage Sx --author claude|gpt`: консилиум разработки по чек-листу `dev-stage` (03, раздел 8).
   `--author` = семейство ИИ, в котором писался код этапа; проверяющие подбираются так, чтобы был хотя бы один другой семьи.
10. `guards.py`: `no_long_dash()`, `is_nap_field()`, `forbidden_phrases()` (список из ТЗ 5.2 и промта `auditor-observations`, плюс «уходит к соседям»,
    «уходят к конкурентам»), `kzt()`. Каждая функция с тестом.
11. `integrations/telegram.py`: `notify(text)` ответственному.
12. Импорт эталона: `source/etalon-50.csv` → `companies` (`source=etalon_2026_09_30`), три `card_snapshots` на компанию
    (`collected_by=manual_import`, `status=verified`, `purpose=prospect`) по словарю `04`, раздел 1; колонка `расхождения` → `audits.discrepancies` как `legacy_text`.
    Пустое значение в CSV сохраняется как `null`.
13. Адаптер `to_score_row()` (`04`, раздел 1.5) и перенос `score()` без изменения логики, пороги в `config/scoring.yaml`.
14. `python -m zhol.cli score-check`: импорт → адаптер → `score()` → сравнение с `балл_итого`.
15. Синтетические золотые наборы для движка: `tests/golden/review-engine/` (минимум 12 случаев: принятое замечание, спор с доказательством,
    critical от одного чужого голоса, замечание только от модели семейства автора, нет кворума, 3 круга без исправления, `unverified` по главному вопросу).
    Модели в этих тестах подменяются заглушками с заранее заданными ответами: проверяется логика движка, а не модели.

## Промт для ИИ-разработчика

```text
Этап S0 сервиса «Жол». Прочитай AGENTS.md, docs/plan/00-README.md, 01-arkhitektura.md, 03-proverka-i-konsilium.md,
04-slovar-dannyh.md и docs/plan/stages/S0.md. Используй скиллы zhol-stage, zhol-council, claude-api, zhol-prompt.

Задача: каркас, движок проверки и консилиум, импорт эталона, перенос балла. Агентов, кроме расчёта балла, на этом этапе нет.

Жёсткие правила:
- Схема базы, статусы, переходы, очередь, обёртка ровно как в 01-arkhitektura.md. Отступление: сначала спроси.
- Движок проверки строго по 03-proverka-i-konsilium.md. Голоса, порог, кворум и вердикт считает код. Модель-секретарь только группирует.
- score() переносится без изменения логики, через адаптер из 04-slovar-dannyh.md раздел 1.5.
- Пустое значение CSV = null, не 0.
- Время только через timeutil.now(), у всех команд флаг --now.
- Секреты только из .env.

Порядок: (1) покажи план файлов и миграцию, дождись «ок»; (2) база, переходы, очередь, обёртка; (3) движок проверки
с синтетическими тестами; (4) импорт эталона и score-check. После каждой части покажи вывод тестов.
В конце: pytest, score-check, eval по review-engine, затем zhol-acceptance S0.
```

| # | Проверка | Как | Ожидаемо |
|---|---|---|---|
| 1 | Сервис поднимается | `docker compose up -d`, `docker compose ps` | 5 контейнеров `running` |
