# S1. Барлау: сбор карточек

**Зависит от:** S0.

## Цель

По id 2ГИС собрать снимки карточки в 2ГИС, Яндекс Картах и Google Maps: все поля словаря, скриншот, источник у каждого поля.
Ничего не вычислять: не видно, значит `null`. Каждый снимок проверен кодом, 10% компаний перепроверены повторным чтением и вторым ИИ.

## Входы

- ТЗ раздел 5.1; `04-slovar-dannyh.md` раздел 1 (ключи и значения); `01` разделы 4.1 и 5 (статусы, цепочка)
- `source/karty-metodika-2026-10.md` раздел 6 (как читать признаки)
- Промты `prompts/scout-extract.md`, `prompts/scout-match.md`; чек-листы `council/checklists/scout_fields.md`, `match.md`
- `source/base-contacts.csv` (550 компаний, только контакты; колонка `etalon` = 1 у 50 компаний эталона)

## Шаги

1. `browser/twogis/public.py`: открыть `https://2gis.kz/almaty/firm/<id>`, полный скриншот, текст блоков и вкладок (отзывы, фото, цены).
   Поля, которые надёжно читаются из разметки, читает код (`field_sources.read_by = code`). Остальные: промт `scout-extract` (`read_by = model`).
2. `browser/yandex/public.py`, `browser/google/public.py`: поиск по «название + адрес», до 5 кандидатов → `scout-match` → перевод вердикта
   в `match_status` (`04`, раздел 1.3). Найдено: разбор как в п. 1. Записать `company_platform_ids` (`external_id`, `public_url`).
3. Снимок на каждую площадку с `purpose` из задачи. Старые снимки не меняются.
4. `snapshot.verify` (код, по одной компании): у каждого непустого поля есть источник, значения по словарю. Прошёл: `verified`.
   Признаки формулы проверяются не по одной компании, а по пачке: команда `python -m zhol.cli scout-batch-check --since <дата>`
   ищет повторяющиеся зависимости между площадками (например, рейтинг Яндекса ровно на 0,1 меньше 2ГИС у всех компаний пачки).
   Запускается после каждого массового сбора; нашла зависимость: снимки пачки `rejected`, `human_task`.
5. Выборка 10% компаний (все три снимка компании): `review.snapshot_recheck` в очереди `browser`:
   повторное чтение 5 полей (рейтинг, оценок, фото, цены, онлайн-запись) и проверка полей `read_by = model` по точке `scout_fields`.
   Больше одного расхождения: `rejected`, новый `scout.collect`. Два `rejected` подряд: `human_task`.
6. Точка `match` для решений `same` без совпадения телефона.
7. Страница не загрузилась или структура неожиданная: `failed` с причиной, 3 попытки, потом `human_task`.
   Карточка не найдена на площадке (`not_found`): скриншот страницы поисковой выдачи по названию и адресу.
8. Импорт `source/base-contacts.csv`: компании, которых ещё нет (эталон уже импортирован в S0, его пропустить), `source=base_550_contacts`.
9. CLI: `python -m zhol.cli scout --ids-file ids.txt --purpose prospect` и `--etalon` (все 50 эталона).
10. `python -m zhol.cli scout-compare`: по 50 эталона поле, значение 30.09, новое значение, совпало или нет, путь к скриншоту.

```text
Этап S1 сервиса «Жол». Прочитай AGENTS.md (5.1, 7), docs/plan/04-slovar-dannyh.md (раздел 1), 01-arkhitektura.md (4.1, 5),
docs/plan/stages/S1.md, prompts/scout-extract.md, prompts/scout-match.md, council/checklists/scout_fields.md и match.md.
Используй скиллы zhol-stage, zhol-browser-script, webapp-testing, zhol-prompt, zhol-council.

Задача: агент-разведчик собирает публичные карточки компании в 2ГИС, Яндекс Картах и Google Maps.

Жёсткие правила:
- Ключи и значения полей только из 04-slovar-dannyh.md.
- Не видно = null с причиной. Не вычислять, не переносить значения между площадками.
- Каждый сбор создаёт новый снимок, старые не меняются.
- Селекторы и адреса в config/platforms.yaml.
- Перепроверка 10% компаний идёт в очереди browser.

Порядок: 2ГИС на 3 салонах эталона, покажи снимки и скриншоты, дождись «ок». Потом Яндекс и Google. Потом все 50 эталона и scout-compare.
Золотые наборы: tests/golden/scout-extract/ и tests/golden/scout-match/ (по 10 случаев), tests/golden/scout_fields/ (10 верных и 5 с ошибками).
В конце zhol-acceptance S1 и council-dev --stage S1.
```

## Приёмка

| # | Проверка | Ожидаемо |
|---|---|---|
| 1 | Прогон по 50 эталона | 150 снимков, у каждого скриншот (для `not_found` скриншот выдачи); `failed` не больше 3, у каждого причина |
| 2 | `scout-compare`, поля 2ГИС: рейтинг, оценок, фото, цены, онлайн-запись, WhatsApp, Instagram | Совпадение не ниже 90% по каждому полю. Каждое расхождение видно на новом скриншоте (за время с 30.09 пришли отзывы, фото) |
| 3 | `scout-compare`, `match_status` Яндекса и Google | Совпадение не ниже 85%; каждое расхождение Ербол проверил по скриншоту и описал |
| 4 | Нет формул | `scout-batch-check` по пачке 50 эталона: зависимостей нет; на подложенной пачке с формулой: найдено |
| 5 | Источник | У 100% непустых полей есть `url`, `seen_at`, скриншот |
| 6 | Перепроверка | Выбрано 5 компаний, результат в `council_runs` точки `scout_fields` |
| 7 | Сломанная страница | Несуществующий id: `failed`, 3 попытки, `human_task` |
| 8 | Золотые наборы | `eval` по `scout-extract`, `scout-match` не ниже 9 из 10; `scout_fields` ловит 5 из 5 ошибок |
| 9 | Ревью | `/code-review` и консилиум разработки: `pass` |

Пороги 90% и 85% это допуск на изменения карточек с 30.09, а не на ошибки чтения. Ошибка чтения при совпадающем скриншоте исправляется.

**Тимуру проверить руками (15 минут):** открыть 3 случайных скриншота из отчёта и сверить с полями снимка в CSV.
