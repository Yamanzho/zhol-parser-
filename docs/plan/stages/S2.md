# S2. Тексер: аудит и экспорт для рассылки

**Зависит от:** S1.

## Цель

По проверенным снимкам посчитать балл, расхождения и пробелы, написать сильную сторону и 1-3 наблюдения, сделать одностраничник,
пропустить через проверяющего и отдать в Syntony для рассылки только проверенное.

## Входы

- ТЗ разделы 5.2, 6.1; `04-slovar-dannyh.md` разделы 1.4-1.5 и 3; `03` раздел 3.1, строка 4
- `zhol/agents/auditor/score.py` и адаптер из S0
- `source/pilot-out/<id>/audit.html`, `audit.png`: **образец только вёрстки**. Тексты в `message.txt` и формулировки вида
  «уровень лучших салонов города», «часть людей уходит к соседям» не использовать: они нарушают запреты ТЗ 5.2
- Промт `prompts/auditor-observations.md`, чек-лист `council/checklists/observations.md`

## Скиллы

`zhol-stage`, `zhol-prompt` (промт и золотой набор), `zhol-council` (точка `observations`), `verification-before-completion`,
`/code-review`, `zhol-acceptance`.

## Шаги

1. `auditor.audit`: последние снимки трёх площадок со статусом `verified`, не старше 14 дней. Старше: `scout.collect(prospect)` и ждать.
2. Код: `derived` (доля ответов, свежесть отзыва), `discrepancies` (название, адрес, рубрика между найденными карточками, `04` раздел 1.4),
   балл через адаптер и `score()`, пробелы с `field_ref` и потерянными баллами.
3. Промт `auditor-observations`. Код проверяет ответ: `field_ref` наблюдений есть в пробелах, `strength.field_ref` есть в полях,
   нет фраз из `guards.forbidden_phrases()`, нет длинного тире. `evidence_url` каждого наблюдения ставит код из `field_sources`.
4. `review.run(point=observations)`. Первые 20 аудитов дополнительно уходят Тимуру (`human_first: 20`).
   До готовой админки (S3) решения Тимура собираются так: `python -m zhol.cli human-review export --point observations` → CSV с одностраничниками,
   Тимур ставит «да» или «нет» с комментарием → `human-review import`. Решения пишутся в `review_quality`.
5. Одностраничник: HTML-шаблон по вёрстке образца, только факты снимков и проверенные наблюдения, PNG через Playwright.
6. Экспорт: `GET /api/v1/export/mailing` (когда будет API в S3) и `python -m zhol.cli export-mailing --out mailing.csv` сейчас.
   Только `audits.status = checked`, `companies.dnc = false`, есть WhatsApp. Ссылка на одностраничник подписанная (`01` раздел 11).

## Промт для ИИ-разработчика

```text
Этап S2 сервиса «Жол». Прочитай AGENTS.md (5.2, 6.1), docs/plan/04-slovar-dannyh.md (1.4, 1.5, 3), 03-proverka-i-konsilium.md
(3.1 строка 4), docs/plan/stages/S2.md, prompts/auditor-observations.md, council/checklists/observations.md.
Используй скиллы zhol-stage, zhol-prompt, zhol-council.

Задача: аудит по снимкам, наблюдения, проверка, одностраничник, экспорт для рассылки.

Жёсткие правила:
- Балл, расхождения, пробелы, evidence_url считает код. Модель пишет только текст сильной стороны и наблюдений.
- Наблюдение без field_ref из пробелов отбрасывается кодом.
- Запрещённые фразы и длинное тире проверяет guards.py.
- source/pilot-out образец только вёрстки, его тексты не копировать.
- Экспорт отдаёт только проверенные аудиты, dnc=false, с WhatsApp. Тест, что остальное не уходит.

Начни с золотого набора: tests/golden/auditor-observations/ (10 компаний эталона с ожидаемыми field_ref)
и tests/golden/observations/ (10 верных ответов и 5 с подложенными ошибками: чужая цифра, чужой field_ref, запугивание,
обещание, непонятный текст). Покажи результат eval, потом остальное. В конце zhol-acceptance S2 и council-dev --stage S2.
```

## Приёмка

| # | Проверка | Ожидаемо |
|---|---|---|
| 1 | Балл по снимкам S1 для 50 эталона | Совпадает с ручным баллом не меньше чем у 40 из 50. По каждому расхождению в отчёте указано, какое поле изменилось и где это видно на скриншоте (в том числе новое правило расхождений, `04` раздел 1.4) |
| 2 | 10 случайных одностраничников | Тимур сверяет каждое наблюдение со скриншотом: 10 из 10 подтверждаются |
| 3 | Тон | Проверка кодом по всем аудитам: 0 запрещённых фраз, 0 обещаний, 0 длинных тире |
| 4 | Проверяющий | `eval --point observations`: 10 из 10 верных проходят, 5 из 5 ошибок пойманы |
| 5 | Экспорт | Непроверенный аудит, `dnc=true`, нет WhatsApp: не попадают (тесты N1, N2) |
| 6 | Первые 20 | Решения Тимура записаны в `review_quality` |

**Тимуру проверить руками (20 минут):** 10 одностраничников из п. 2 и CSV `human-review` для первых 20.
