# S5. Шебер в браузере: доступы, внесение правок, модерация

**Зависит от:** S4.

## Цель

Утверждённые правки, ответы на отзывы и жалобы вносятся в кабинеты 2ГИС, Яндекс Бизнеса и Google Business Profile без человека:
проверка доступа, скриншот до и после каждой правки, журнал, остановка на незнакомом экране, проверка модерации, откат.

## Входы

- ТЗ разделы 5.4 (часть 2), 9; `01` разделы 3 (`company_platform_ids`, `browser_profiles`, `credentials`, `change_items`, `change_log`), 4.2, 5, 12, 13
- Чек-лист `council/checklists/applied.md`
- Карточка AOE: в 2ГИС организация 70000001063417057. Тимур вносил правки в трёх кабинетах через браузер 30.09.2026, вход сохраняется
- **От Тимура до начала этапа:** доступ к аккаунтам Duna с правами менеджера на карточке AOE в трёх кабинетах (лично, не в чате);
  материалы AOE для тестового заказа: логотип, 10-20 реальных фото, прайс услуг, график, тексты (список в `START.md`)

## Скиллы

`zhol-stage`, `zhol-browser-script` (главный), `webapp-testing`, `zhol-council` (точка `applied`), `/security-review` (профили, пароли),
`verification-before-completion`, `/code-review`, `zhol-acceptance`.

## Шаги

1. Профили браузера (`browser_profiles`): `duna-main` на каждую площадку. Первый вход: `python -m zhol.cli browser-login --platform X --account duna-main` (человек).
   Если клиент дал логин и пароль: `--account client-<company_id>` расшифровывает пароль только внутри этой команды, код подтверждения вводит человек вместе с клиентом.
2. `intake.access_check` (по `POST /access-granted`): открыть кабинет, найти организацию клиента, записать `external_id` и `cabinet_url`,
   `access_status = verified`. Не нашлась: `human_task` «клиент не добавил доступ» и событие `intake_missing`.
3. Проверка сессии перед каждой задачей: нет входа или просят код → профиль `needs_login`, `human_task`, правки не начинаются.
4. Сценарии `browser/<platform>/edit_*.py` по типам: описание, услуги и цены, график, фото, ответ на отзыв, жалоба на отзыв, акция или новость,
   сайт и соцсети, поля названия, адреса, телефона, рубрики, создание карточки (`create_card`).
   Запись через `playwright codegen` на карточке AOE, селекторы в `config/platforms.yaml`. Тот же проход сверяет черновик `editable_fields` из S4
   с кабинетами; отличия в `docs/decisions.md`.
5. `create_card`: если карточки на площадке нет (`match_status = not_found`), агент создаёт её по профилю клиента. Подтверждение владельца
   (звонок, СМС, открытка) делает человек: `human_task` с инструкцией для клиента. Правка получает `waiting_owner_verification`;
   заказ её не ждёт ни для доступа, ни для модерации, в отчёте «ждёт подтверждения владельца».
6. Каждая правка: проверка, что открыта нужная организация (`company_platform_ids.external_id`) → текущее значение уже равно «станет»? → `already` →
   иначе скриншот до → действие → сохранение → признак успешного сохранения → скриншот после → `change_log`.
7. Незнакомый экран, элемент не найден за 15 секунд, неожиданное окно: `stopped_unknown_ui`, скриншот, `human_task`. Кликов наугад нет.
8. `review.run(point=applied)` по каждой правке + код: в `change_log` нет правок, которых нет среди утверждённых.
9. `executor.moderation_check` через 24 ч (`timeutil.now()`): публичная карточка = «станет» → `moderation_ok`. Не видно: ещё 2 раза через 24 ч,
   потом `moderation_pending_long` (в отчёте «ещё на модерации»). Отказ, видимый в кабинете: исправление и повторная подача один раз, потом `human_task`.
10. Откат: `python -m zhol.cli rollback --change <id>` возвращает `before`, со скриншотами.
11. Тестовый заказ AOE: заказ в `stub`, оплата подтверждением в админке, материалы AOE, пакет S4, утверждение Тимуром.
    Баннер для акции до S6 Ербол делает вручную и загружает как файл клиента.

## Приёмка

Тестовый заказ AOE. Каждый тип правки на каждой площадке, где этот тип есть:

| # | Проверка | Ожидаемо |
|---|---|---|
| 1 | Описание, услуги и цены, фото, ответ на отзыв, акция или новость | Внесено, скриншоты до и после, запись в журнале, точка `applied` `pass` |
| 2 | Повторный запуск того же пакета | Всё `already`, ничего не изменено |
| 3 | Подмена селектора на несуществующий | `stopped_unknown_ui`, скриншот, `human_task` (N17) |
| 4 | Открыта другая организация перед сохранением | Остановка (N16) |
| 5 | Выход из сессии | Правки не начинаются, профиль `needs_login`, `human_task` |
| 6 | Модерация с подменой времени | `--now` +24 ч, +48 ч, +72 ч: у каждой правки `moderation_ok`, объяснённый отказ или `moderation_pending_long` |
| 7 | Откат одной правки | Значение вернулось, скриншот есть |
| 8 | Лишняя правка в очереди на внесение | Не вносится (N15) |
| 9 | Проверка доступа | Для AOE `access_status = verified` на трёх площадках; для выдуманной организации `human_task` |
| 10 | Профили и пароли | Права 700, вне репозитория; поиск тестового пароля по логам: 0 |

После приёмки S5 можно брать первых реальных клиентов: первые 10 пакетов Тимур одобряет до отправки клиенту (`human_first`, блокирующая проверка).

**Тимуру проверить руками (20 минут):** открыть карточку AOE на трёх площадках и сравнить с отчётом журнала.
