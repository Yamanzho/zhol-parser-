# S9. Управленец, журнал качества, полная админка

**Зависит от:** S3. Можно вести параллельно с S5-S8; сроки и сводка подключают точки по мере их готовности.

## Цель

Ни одна задача не зависает незаметно. Ответственный человек каждый день видит, что происходит, и получает только то, что требует человека.
Журнал качества проверки работает: еженедельный выборочный аудит и ежемесячный разбор по моделям.

В ТЗ управленец назван «Сарай». Это модуль Жола, а не существующий бот-ассистент AOE; связывать их не нужно.

## Входы

- ТЗ раздел 5.7 (сроки, запреты); `01` разделы 5, 13; `03` разделы 3.1 строка 16, 7
- Промт `prompts/manager-digest.md`

## Скиллы

`zhol-stage`, `zhol-prompt`, `zhol-council` (еженедельный аудит, журнал качества), `webapp-testing` (админка), `/security-review`,
`verification-before-completion`, `/code-review`, `zhol-acceptance`.

## Шаги

1. `config/sla.yaml` со сроками ТЗ 5.7. Рабочие дни пн-пт, Asia/Almaty. Этапы ожидания клиента (`prepay_invoiced`, `intake`, `client_review`,
   `invoiced`) просрочкой исполнителя не считаются.
2. `manager.sla_scan` каждые 15 минут: просрочка → повторный запуск задачи агента; вторая просрочка → `human_task` и Telegram.
3. `manager.digest` в 9:00: цифры кодом (компании и заказы по этапам, просрочки с причиной, задачи «нужен человек» со ссылками,
   вердикты проверки за сутки, расход на модели за сутки в тенге по курсу из `models.yaml`). Текст через `manager-digest`;
   код проверяет, что каждое число в тексте есть в данных. Отправка в Telegram.
4. `review.weekly_audit` по понедельникам: 10% работ, прошедших уровень «один проверяющий» без замечаний за неделю, задним числом
   через консилиум. Найден critical: точка временно переводится на консилиум (флаг в `review_policy`), `human_task` на разбор.
5. Ежемесячный разбор качества (1-го числа): по каждой модели и точке доля подтверждённых человеком замечаний и число пропусков
   (`review_quality`). Предложение по весам и составу в Telegram Тимуру. Конфиг меняет только Тимур.
6. Админка, дополнение к S3: компании, заказы с этапами, карточка заказа (пакет, журнал правок, скриншоты, итоги проверок с голосами),
   отзывы, счета, отчёты, журнал качества.

## Промт для ИИ-разработчика

```text
Этап S9 сервиса «Жол». Прочитай AGENTS.md (5.7), docs/plan/01-arkhitektura.md (5, 13), 03-proverka-i-konsilium.md (3.1 строка 16, 7),
docs/plan/stages/S9.md, prompts/manager-digest.md. Используй zhol-stage, zhol-prompt, zhol-council, webapp-testing.

Задача: управленец (сроки, тревоги, сводка), еженедельный аудит проверки, ежемесячный разбор качества, полная админка.

Правила:
- Цифры сводки и разбора считает код; модель только формулирует. Числа текста сверяются кодом.
- Управленец не меняет статусы оплаты и согласия клиента и не пишет клиенту.
- Ожидание клиента не просрочка исполнителя.
- Проверять расписание через --now, без реального ожидания.

Покажи сводку, еженедельный аудит и админку. Если S4-S8 ещё не готовы, используй синтетические данные (фикстуры в tests/fixtures/s9/),
созданные по схеме базы: заказы на разных этапах, пакеты, правки, итоги консилиума.
В конце /security-review, zhol-acceptance S9, council-dev --stage S9.
```

## Приёмка

| # | Проверка | Ожидаемо |
|---|---|---|
| 1 | Застрявшая задача, `--now` вперёд на срок + 15 минут | Повторный запуск, затем тревога в Telegram |
| 2 | Заказ ждёт материалы клиента 5 дней | Не просрочка |
| 3 | `--now 09:00` | Сводка пришла; все числа совпадают с SQL-запросами, приложенными к отчёту |
| 4 | Еженедельный аудит | Отобрано 10% работ (реальных или из фикстур), результаты в `review_quality` |
| 5 | Ежемесячный разбор | Сообщение Тимуру с долей подтверждённых замечаний по каждой модели |
| 6 | Админка | Тимур находит заказ, видит пакет, журнал, скриншоты и голоса консилиума |

**Тимуру проверить руками (15 минут):** сводку в Telegram и карточку тестового заказа AOE в админке.
